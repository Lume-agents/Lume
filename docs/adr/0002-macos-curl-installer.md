# Instalação macOS via curl enquanto não há Developer ID

Até a assinatura Developer ID + notarização (#13), o `dmg` baixado pelo navegador recebe quarentena e o Gatekeeper o bloqueia; desde o Sequoia o bypass exige Ajustes do Sistema → Privacidade e Segurança → "Abrir Mesmo Assim". Como caminho provisório, o macOS é distribuído como **preview** por `scripts/install-macos.sh`, executado com `curl -fsSL https://raw.githubusercontent.com/Lume-agents/Lume/main/scripts/install-macos.sh | sh`. Arquivos baixados por `curl` não recebem quarentena, então o app abre sem bypass.

Considered Options: (a) documentar o bypass do Gatekeeper para o `dmg` — rejeitado por ser um fluxo de quatro passos que treina o usuário a ignorar avisos de segurança; (b) Homebrew cask — rejeitado porque o Homebrew anunciou a desativação de casks que falham no Gatekeeper; (c) script via `curl` — escolhido. Hospedagem em `raw.githubusercontent.com` na `main`: sem infraestrutura nova; a URL é contrato público e o arquivo não deve mudar de caminho. O script baixa o `.app.tar.gz` da Release (a versão vem do `latest.json`), nunca remove quarentena nem altera o Gatekeeper, e verifica o download apenas por HTTPS (o `.sig` é minisign, ausente no macOS).

Consequences: o README cita o macOS como preview; o critério de #14 ("README/landing só citam macOS com smoke verde") passa a valer para o suporte oficial. A build segue com assinatura ad-hoc, cujo identificador muda a cada versão, então a permissão de Automação do Terminal.app pode ser pedida de novo após updates. Quando #13 fechar, o `dmg` volta a ser o caminho padrão e esta ADR deve ser substituída; o script pode continuar existindo para quem prefere instalar pelo terminal.
